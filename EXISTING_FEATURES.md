# HealPoint 2.0 — Existing Features Inventory & Gap Analysis

**Status:** Audit Complete — Existing vs Required Modules Cataloged

## 1. Feature Map: What Exists vs What is Needed

| Requested Phase | Feature Name | Current Implementation in Codebase | What Needs Improvement / Next Steps |
|---|---|---|---|
| **Phase 1** | **Live Queue Management** | • `appointmentModel`: `queueToken`, `queueStatus`, `checkedIn`, `checkInAt`, `calledAt`.<br>• `checkInController.js`: `getAppointmentLiveQueueStatus`, `processCheckIn`, `processScanCheckIn`, `getHospitalQueueOverview`.<br>• `doctorController.js`: `getDoctorQueue`, `handleDoctorQueueAction`.<br>• `CheckInScannerView.jsx`: QR scan & check-in UI for Hospital Admin. | • Attach Socket.IO to `HealPointBackend` with multi-instance Redis adapter capability.<br>• Dynamic estimated wait-time calculation based on average consultation durations.<br>• Hospital-scoped socket broadcasts (`hospital:${hospId}`, `doctor:${docId}`). |
| **Phase 2** | **Advanced Video Consultation** | • `consultationRoutes.js`: Online doctor listing, meeting URL storage, consultation status (`waiting`, `doctor_ready`, `ready_to_join`, `in_progress`, `completed`).<br>• `app/consultation/video-room.tsx`: Patient video room screen.<br>• `OnlineConsultationsView.jsx`: Web consultation list. | • Currently relies on external URL generation (e.g., Google Meet links).<br>• Needs secure WebRTC-compatible session auth, appointment-bound tokens, waiting room state machine, start/end timestamps, reconnection handling. |
| **Phase 3** | **AI Health Assistant** | • `aiController.js`: Rule-based emergency keyword detector (108/112), symptom-to-specialty mapper, active doctor suggestions with safety disclaimers.<br>• `app/ai-assistant.tsx`: 53KB interactive chat screen in mobile client.<br>• `aiRoutes.js`: `POST /api/v1/ai/chat`. | • Integrate official Gemini API (`@google/genai`) with guardrails.<br>• Strict safety filters: disclaimer injection, emergency escalation (112), prompt injection resistance, zero PHI leakage to external models. |
| **Phase 4** | **Smart Health Wallet** | • `healthDocumentModel.js`: EMR categories (`prescription`, `lab_report`, `radiology`, `discharge_summary`, `vaccination`, `other`), Base64/cloud file data, shared doctor permissions.<br>• `appointmentController.js`: `getHealthWallet` (aggregates prescriptions, lab reports, bills, receipts, visit passes, and user documents into a unified timeline with family filtering).<br>• `app/(drawer)/health-wallet.tsx`: 3,010-line comprehensive digital health locker. | • Replace pure Base64 payloads with pre-signed secure cloud storage URLs for scalability.<br>• Time-limited, revocable doctor access consent tokens.<br>• Hospital admin and super admin tenant-restricted document access. |
| **Phase 5** | **Digital Prescription & Medicine Reminders** | • `doctorController.js`: `saveDoctorAppointmentPrescription`, `getDoctorPrescriptions`, medicines array with dosage, frequency, duration, instructions.<br>• `appointmentController.js`: `getPatientMedicationReminders`, `updateMedicationDoseStatus`, `createMedicationReminder`.<br>• `reminderScheduler.js`: Background reminder scheduler checking 24h and 1h upcoming appointments. | • Standardized PDF prescription generation using jsPDF.<br>• Medication reminder push/in-app notification scheduling with UTC timestamps and timezone conversion. |
| **Phase 6** | **Advanced Analytics** | • `hospitalAdminController.js`: `getDashboard`, `getHospitalAppointments` with date-range filters.<br>• `doctorController.js`: `getDoctorEarnings`, `getDoctorAnalytics`.<br>• `userController.js`: `getStats`, `getAnalytics`, `getPlatformUsers`.<br>• `HealPointSuperAdminWeb`: Platform analytics and earnings views. | • Optimize MongoDB aggregation pipelines for high volume.<br>• Support IST timezone conversions and CSV/PDF export options. |
| **Phase 7** | **Emergency SOS** | • `userModel.js`: `emergencyContact` (`name`, `phone`, `relation`).<br>• `app/(drawer)/emergency.tsx`: 41KB emergency screen with emergency calling, 108 / 112 hotline support, location sharing.<br>• `aiController.js`: Emergency red-flag detection. | • Indian emergency number 112 verification.<br>• Fallback mechanisms for offline / weak network situations. |
| **Phase 8** | **Verified Reviews & Feedback** | • `reviewModel.js`: `rating`, `comment`, `isApproved`, `doctorId`, `userId`, `appointmentId`.<br>• `reviewController.js`: Submit review, doctor review retrieval.<br>• `HealPointHospitalAdminWeb` & `HealPointDoctorWeb`: Reviews views. | • Enforce verified booking check (reviews only permitted after `appointment.status === 'completed'`).<br>• Duplicate review prevention (one review per appointment). |
| **Phase 9** | **Multilingual Support** | • Hardcoded English strings across screens and portals. | • Create centralized localization dictionaries (English, Hindi, Gujarati).<br>• Implement language switcher with persistence in storage/DB.<br>• Prevent accidental translation of doctor names, hospital names, and medical IDs. |
| **Phase 10** | **Smart Notification Center** | • `notificationModel.js`: `userId`, `doctorId`, `hospitalId`, `title`, `message`, `type`, `read`.<br>• `emailService.js`: Nodemailer HTML reminder emails.<br>• `reminderScheduler.js`: Recurring timer scheduler. | • Transition from in-memory setInterval to a persistent queue (e.g. BullMQ / Agenda) with retry backoff and idempotency.<br>• Notification preference settings per channel (in-app, push, email). |
| **Phase 11** | **Family & Dependent Profiles** | • `userModel.js`: `familyMembers` array with demographics, relations, allergies, conditions.<br>• `userController.js`: `addFamilyMember`, `getFamilyMembers`.<br>• `appointmentModel.js`: `familyMemberId`, `familyRelationship`, `isFamilyBooking`.<br>• `FamilyMemberFilterBar.tsx`: UI filter in Health Wallet. | • Ensure dependent wallets, prescriptions, and booking operations are cleanly isolated per family member.<br>• Consent controls for adult dependents. |
| **Phase 12** | **Hospital Subscription & Plans** | • `subscriptionPlanModel.js`: Plan key, name, monthly/yearly price, features, quotas.<br>• `subscriptionController.js`: Patient subscriptions with Razorpay integration.<br>• `HealPointSuperAdminWeb`: Subscription management views. | • Extend subscription framework to Hospital Tenants (Tiered plans: Basic, Pro, Enterprise with doctor limits and storage caps).<br>• Enforce server-side hospital feature limits. |
| **Phase 13** | **Waitlist & Slot Recommendation** | • `slotHelper.js`: `generateDoctorSlotsForDate`, `getHourlyBookingCount`, `MAX_HOURLY_CAPACITY`.<br>• `appointmentController.js`: Concurrency check rejecting bookings when hourly limit is reached. | • Add dedicated Waitlist collection for over-capacity slots.<br>• Auto-notify waitlisted patients when cancellations occur.<br>• Race-condition-safe atomic slot claim. |
| **Phase 14** | **Privacy & Compliance (DPDP Act 2023)** | • `auditLogModel.js`: Hospital audit logs with actor, action, client IP, device, timestamp.<br>• `hospitalAdminController.js`: `getHospitalComplianceOverview`, `getHospitalAuditTrail`, `exportHospitalComplianceCSV`.<br>• `app/(drawer)/privacy.tsx`: 87KB privacy screen. | • Patient-facing data access log (see who accessed their records).<br>• Data export (full medical data download) and account deletion workflow respecting legal medical retention periods. |
| **Phase 15** | **Lab Test Booking & ABHA Readiness** | • `healthDocumentModel.js`: `category: "lab_report"`.<br>• Health wallet lab report viewing. | • Hospital lab test catalog, test booking, and automatic health-wallet linking.<br>• Optional ABHA (ABDM) ID field with graceful unconfigured fallback (zero mock verification). |
| **Phase 16** | **PWA, Dark Mode & Accessibility** | • `public/manifest.json`, `public/sw.js` (PWA service worker already configured).<br>• `constants/theme.ts`: Royal Blue (`#2563EB`), Sky Blue (`#60A5FA`), White (`#FFFFFF`), Light Gray (`#F8FAFC`), Text (`#1E293B`). | • Standardize dark-mode theme across web portals and mobile.<br>• Ensure WCAG 2.1 AA contrast and keyboard accessibility. |
| **Phase 17** | **Final Integration & QA** | • Existing test baseline: 7 passing unit tests, 0 TypeScript errors. | • End-to-end integration test suite, tenant-isolation verification, concurrent booking load tests. |
